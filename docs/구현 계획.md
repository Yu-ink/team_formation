# 구현 계획

## 1. 기술 구성
| 부분 | 선택 | 이유 |
|---|---|---|
| 화면 | Streamlit(Community Cloud 배포) | 공고 요구. `st.fragment`로 부분 갱신 |
| DB | Supabase PostgreSQL, `psycopg` 3 + 연결 풀 | 유일성 제약·행 잠금으로 동시성 처리 |
| AI | OpenRouter 무료 모델 3개(1·2·3차) | 실패 시 다음 모델, 3차 실패 시 앱 직접 배정 |
| 해시 | `bcrypt` | 비밀번호 원문 저장 금지 |
| DB 깨우기 | GitHub Actions 예약 실행 | 외부 예약 서비스로 매일 질의 |

## 3. 기능별 해결 방법(3장 표) — 모두 어려운 해결
| 기능 | 고른 해결 | 구현 위치 |
|---|---|---|
| 다른 사람의 변경 보기 | 어려운 해결: `st.fragment(run_every=5)`로 팀 목록·투표 영역만 5초마다 다시 그림 | `student_board`, `admin_board` |
| 필수 포함 역할을 지킬 수 없는 팀 | 어려운 해결: 지원 단계에서 자리가 모자라게 되는 지원은 막음(승인 직전에도 다시 검사) | `rules.join_block_reason` |
| 같은 팀에 대기 중인 지원이 여럿 | 어려운 해결: 승인 직전에 규칙 재검사. 처리 순서는 투표가 끝난 순서(팀 행 잠금) | `service._vote` |
| 마지막 자리에 두 명이 동시에 | 어려운 해결: `tf_members (team_id, slot_no)` 기본 키 + `student_id` unique + 대기 지원 부분 유일 인덱스 | `schema.sql`, `service._add_member` |
| AI 응답이 늦을 때 | 어려운 해결: 요청을 다른 스레드에서 보내고 모델마다 120초 전체 시간을 재서 끊음 | `ai.assign` |
| 3차 모델까지 실패 | 어려운 해결: 백트래킹으로 모든 경우를 따져 검사 5가지를 통과하는 배정을 끝까지 찾음 | `rules.solve` |
| AI 대기 중 화면 | 어려운 해결: "2차 모델(…)의 응답을 기다리는 중… 37초 / 120초"를 매초 갱신 | `run_assign` |
| DB 일시정지 막기 | 어려운 해결: GitHub Actions로 매일 DB 질의 | `keepalive.yml` |

## 4. 화면 key 표(공고 2.7절)
| 화면 요소 | Streamlit 요소 | key |
|---|---|---|
| 학번 / 비밀번호 / 로그인 | text_input / text_input / form_submit_button | `login_student_no` / `login_password` / `login_submit` |
| 로그인한 사람 | container | `whoami` |
| 결과 안내 | container | `result` |
| 팀 하나 / 지원 단추 | container / button | `team_1`… / `apply_1`… |
| 찬성 / 거부 | button | `vote_yes_{지원자 학번}` / `vote_no_{지원자 학번}` |
| 명단 CSV / 팀 수 / 처음 상태 | file_uploader / number_input / button | `admin_roster_file` / `admin_team_count` / `admin_start` |
| 모집 마감 / 팀 없는 학생 | button / container | `admin_close` / `unassigned` |
| AI 배정 / 진행 안내 / 확정 | button / container / button | `admin_assign` / `assign_status` / `admin_confirm` |

새로 고침 단추(`refresh`)는 쉬운 해결용이므로 만들지 않는다.

## 5. 처리 흐름

### 지원
1. 팀 행 잠금(`FOR UPDATE`) → 상태 읽기
2. 마감? 이미 팀? 대기 지원? → 막힘
3. `join_block_reason`: 꽉 참 / 주 역할 중복 / 필수 역할 자리 부족 → 막힘
4. 빈 팀이면 바로 팀원(승인), 아니면 대기

### 투표
1. 팀 행 잠금 → 투표자가 그 팀 팀원인지, 이미 투표했는지 확인
2. 거부 → 바로 거절
3. 찬성 → 지금 팀원 모두 찬성했으면 **승인 직전 재검사** → 통과하면 팀원(승인), 어기면 거절

### 마감 → 배정 → 확정
1. 모든 팀 행 잠금 → 대기 지원 거절 → 1명 팀 비우기 → closed=1
2. `rules.solve`가 None이면 AI를 부르지 않고 이유 표시
3. 1·2·3차 모델(각 120초) → 검사 5가지 → 실패 시 다음 → 모두 실패 시 `rules.solve`
4. 확정 때 지금 상태로 검사 5가지를 다시 하고 저장
